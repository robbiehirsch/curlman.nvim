1. INTRODUCTION                                          *curlman-introduction*

curlman reads Postman Collection v2.1 exports, sends the requests with `curl`,
and shows responses — status, timing, size — either in a quick pane or a
two-panel workspace where each request keeps its own response history you can
diff, filter, and save.

The only hard dependency is `curl`. `jq` is used if present; `node` is only
needed for the (planned) pre-request/test script runner.

==============================================================================
2. REQUIREMENTS                                          *curlman-requirements*

  - Neovim 0.8+ (0.10+ uses |vim.system()|, older falls back to |jobstart()|)
  - `curl` on $PATH
  - Optional: `jq`, and telescope.nvim (+ telescope-ui-select)

==============================================================================
3. INSTALLATION                                          *curlman-installation*

With lazy.nvim: >lua
    {
      "robbiehirsch/curlman.nvim",
      dependencies = { "nvim-telescope/telescope.nvim" }, -- optional
      config = function()
        require("curlman").setup({})
      end,
    }
<
With packer.nvim: >lua
    use({ "robbiehirsch/curlman.nvim", config = function()
      require("curlman").setup({})
    end })
<

4. SETUP & CONFIGURATION                                        *curlman-setup*

                                                              *curlman.setup()*
require("curlman").setup({opts})

Call once. Creates the |curlman-commands|, loads any configured collections and
secrets, and (optionally) installs default keymaps. Full defaults: >lua
    require("curlman").setup({
      collection      = nil,   -- path or list of paths to *.postman_collection.json
      collection_dirs = {},
      environment     = nil,
      secrets_file = vim.fn.stdpath("data") .. "/curlman.local.json",
      shell_env = true,
      shell_env_prefix = "",
      prompt_missing = true,
      curl = {
        connect_timeout = 10, max_time = 30,
        follow_redirects = true, insecure = false,
        http_version = nil, extra_args = {},
      },
      runner = {              -- :CurlmanRunCollection, see |curlman-runner|
        mode = "auto",        -- "auto" | "postman" | "newman"
        assertions = "strict",-- how a failed pm.test affects success
        bail = false, insecure = false,
        timeout_request = nil, iteration_data = nil, iteration_count = nil,
        extra_args = {},
      },
      ui = {
        split = "vertical", size = 0.5,
        left_width = 0.34, preview_lines = 12,
        body_width = 0.85, body_height = 0.85,
        pretty_json = true, jq_pretty = true,
      },
      history = { enabled = true, max_recent = 10, autosave = false },
      keymaps = false, -- true installs <leader>C* maps
    })
<

5. COMMANDS                                                  *curlman-commands*

                                                                    *:Curlman*
:Curlman            Pick a request and send it (quick pane).
                                                                  *:CurlmanUI*
:CurlmanUI          Toggle the two-panel workspace.
                                                                 *:CurlmanRun*
:CurlmanRun         Re-send the last request.
                                                                *:CurlmanLoad*
:CurlmanLoad [f]    Load a collection; no arg opens the project load menu.
:CurlmanLoadEnv [f] Load an environment.
:CurlmanEnv         Choose the active environment.

:CurlmanProfiles    Manage variable profiles: edit the backing file,
                    rename, duplicate, delete, save a copy to a location,
                    toggle favourite. Profiles are named variable sets
                    stored globally as Postman-environment JSON.
:CurlmanProfileSave [name]
                    Snapshot the variables a collection currently resolves
                    against (including unsaved in-memory tweaks) into a
                    named profile.
:CurlmanRunWith     Pick a request, multi-select profiles, run it once per
                    profile; two profiles auto-open a diff tab, three or
                    more offer a pair picker. History entries are tagged
                    with the profile name.
:CurlmanFav         Toggle favourite on an endpoint; favourites float to
                    the top of pickers (as do favourite profiles).
:CurlmanInfo        Timing + response headers for the last response.
:CurlmanDiff        Diff the last request's responses.
:CurlmanHistory     Open the workspace.
:CurlmanClear       Clear all history.
:CurlmanSave        Save the last response to a file.
:CurlmanCopy [k]    Copy request|response|both to a buffer.
:CurlmanJq [expr]   Filter the last response through jq.
:CurlmanReload      Reload collections & secrets.
:CurlmanDemo        Load the bundled demo collection.

6. WORKSPACE                                                *curlman-workspace*

Left panel (configs): <CR> run request / fold / edit variable, `e` edit var,
`o` reset overrides, `y` copy request as curl, `R` reload, `D` remove, `l`
load. Variables show their source: `·env`, `·set` (override), `·needs value`.

Right panel (requests & history): <CR> open response / fold, `t` cycle the
latest-response preview (truncated -> full -> hidden), `y` copy, `x` clear this
request, `X` clear all, `c`/`C` cap, `d` diff, `s` save, `i` info.

`q`/`<Esc>` close, `?` help. In the diff view, `q`/`gt` returns.

==============================================================================
7. VARIABLES & SECRETS                                      *curlman-variables*

{{variable}} placeholders resolve in order (first hit wins): in-memory
overrides > session values > secrets file > shell env > active environment >
collection variables > dynamic ({{$guid}}, {{$timestamp}}, {{$isoTimestamp}},
{{$randomInt}}). Anything unresolved at send time is prompted for.

The secrets file (`secrets_file`) is a gitignored JSON map, defaulting outside
your config so tokens never get committed. Names containing token/secret/
password/key are masked in the UI.

8. COLLECTION RUNS (POSTMAN CLI)                               *curlman-runner*

                                                      *:CurlmanRunCollection*
:CurlmanRunCollection [folder]
        Run a whole loaded collection through the real Postman collection
        runner instead of curl, optionally scoped to one folder.

                                                             *:CurlmanRunner*
:CurlmanRunner
        Report which runner was found, or how to install one.

curl cannot execute Postman's JS sandbox. The CLIs can, so a collection run
gives you pre-request/test scripts, `pm.test` assertions, and variables
chained between requests via `pm.environment.set`.

Either CLI works; `runner.mode` picks one ("auto" prefers the official CLI): >
    postman   brew install postman/tap/postman-cli
    newman    npm install -g newman
<
Neither is a dependency — without them curlman stays a curl-only client.

Every execution in the run is recorded as an ordinary history entry, so
saving, capping, organizing and diffing work exactly as for curl responses.
Buckets are keyed on collection + method + name, so a CLI response and a curl
response for the SAME request share a bucket and can be diffed against each
other with `d` in the workspace.

The runner receives a Postman environment built from curlman's own resolved
variables (see |curlman-variables|), so overrides, secrets, shell env and the
active environment all apply with their usual precedence.

FAILURES

A transport failure (DNS, refused, TLS, timeout) is never a success: the pane
shows "REQUEST FAILED", the error, and the URL. A failed `pm.test` is
configurable, since the request itself may have returned a good body: >
    runner = { assertions = "strict" }   -- default: failed assertion fails it
    runner = { assertions = "lenient" }  -- assertions never affect success
<
Either way the assertion detail renders ABOVE the body rather than replacing
it, so a failed response never costs you the body. HTTP status does not decide
success — curl exits 0 on a 404, and the two engines must agree or their
entries stop being comparable in one history bucket.

Options live under `runner` — see |curlman.setup()|. Single-request sends
always use curl; this is a collection-level operation only.

9. TELESCOPE                                                *curlman-telescope*

Installing telescope-ui-select makes every curlman prompt a Telescope picker.
The bundled extension adds, after
`require("telescope").load_extension("curlman")`: >
    :Telescope curlman requests   fuzzy-find a request (preview: resolved curl)
    :Telescope curlman history    browse responses (preview: the body)
<
